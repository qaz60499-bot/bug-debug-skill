# 09 — Packed / Obfuscated / Anti-analysis

> 面向自有或明确授权软件的可理解性、兼容性与安全审计。

## 第一原则

保护机制只是分析障碍，不自动成为分析目标。先判断它是否真的阻塞当前问题。

## 常见信号

- 高熵 section 或异常 entrypoint；
- 很少的静态导入、运行时解析；
- 控制流平坦化；
- 字符串运行时恢复；
- 虚拟机式解释器；
- 调试环境检测；
- managed obfuscator 痕迹。

## 决策

```text
当前问题能否从外围静态证据回答？
  ├─ 能 → 不额外处理保护层
  └─ 不能
      → 找到最小阻塞点
      → 只恢复回答问题所需语义
```

## 原生 PE 多层保护的优先证据路径

遇到高熵可执行段、异常入口、可写可执行的 staging 段时，先检查 PE TLS callback / 导入解析 / 入口前内存状态；不要直接把磁盘中的加密字节线性反汇编为程序机制。TLS 函数地址应由原始 PE TLS Directory/Callback Table 固定，随后用已实际通过机器指令自测的 decoder 定点解码，解析 RIP 相对引用时交叉核实 IAT 名称与源 RVA。

当汇编显示**有界且可逆**的数据变换（如 RVA、长度、四字节 key table、XOR/ROL 循环），允许在**独立内存副本**离线重现函数变换，保留原始文件 SHA、转换区域/哈希、逆变换或差分校验，再重新对原入口和关键路径做定点反汇编。严禁将“解码出了看似正常的汇编”直接提升为实际运行时验证；API 导入、段名、动态保护调用也不能单独证明已经发生。

若后续仍出现 VM/控制流平坦化/多阶段互校，只选择已定位到的 dispatch、handler、状态机或错误路径继续追踪；保持 ISA、指令语义、运行时行为与最终答案为 Unknown，直到得到可复现实证。真实案例和失败边界见 `research/live-tests/20261009-v3-x64/`（研究证据不作为分发 Skill 的依赖）。

## 语义恢复

优先恢复函数边界、常量、字符串、调用关系、数据结构和状态变化。不要把“还原得像源码”当成目标。

## 证据

始终保留原始样本，并记录“原始状态 → 观察到的保护行为 → 分析后解释”，避免只留下处理后的产物。
